# Languages: English, Kiswahili, Français, Deutsch

## How it works
- **Every language has its own address.** `/sw/stay` is Kiswahili, `/fr/stay` French, `/de/stay` German; English has no prefix (`/stay`). That is what search engines need, and a shared link opens in the language it was shared in.
- **A language is never forced.** The site does not switch language because of the visitor's browser settings or location. If the browser lists Kiswahili, French or German before English, a quiet banner **asks once**, in that language: "Ungependa kuendelea kwa Kiswahili?" The visitor can accept, or say "No thanks" (remembered for six months). Nothing happens without a click.
- **The choice is remembered** in a cookie (`taita-lang`), set when someone opens a `/sw`, `/fr` or `/de` page. After that, a plain link such as `/stay` takes them to `/sw/stay`. Choosing English (the switcher goes through `/en/…`) clears it. Search engines send no cookie, so they always see English at the plain address.
- **The switcher** (globe button in the header, a "Language" row in the phone menu and in the footer) lists each language in its own name, with no flags, as ordinary links to the same page.
- **The API, admin and partner areas, images and files are never given a prefix.** The admin sign-in rule runs first, exactly as before.

## Putting text into a language
The English text is the key. In a **server** component write `tr("Find your Taita")`; in a **client** component, `const { tr, lp } = useI18n()`. For text kept in a list, mark it with `T("Wild")` and translate where it is shown: `tr(item.label)`. Put each link through `lp("/stay")` so it keeps the language. Add the translation to `lib/i18n/messages/sw.ts`, `fr.ts` and `de.ts`. A missing translation simply shows the English, so nothing breaks.

Rules the checks enforce: one text per `tr()` call; a `{variable}` must appear unchanged in every language; every marked text must exist in every language and no language may keep a text nothing uses; a text left identical to English is allowed only for brand names and shared words.

```
node scripts/i18n-keys.mjs          # list every marked text
node scripts/i18n-keys.mjs --check  # fails if any language lacks a text, or keeps one nothing uses
```

**Never put a client component's import on the server translator** (`@/lib/i18n/server`) and never call `useI18n` in a server component: a test fails if you do.

## What is translated now
The header and phone menu, the footer, the language banner and switcher, the whole homepage, the Taita Guide's main texts, the share bar, and the carousel's screen-reader text.

## What is NOT translated yet
- **About 150 other pages** (stays, experiences, events, shop, the planner, account and so on). They show in English inside a translated header and footer. Add them group by group with the steps above.
- **Content from the database** (story text, listing names and descriptions, product names). That needs a translations table and a human review step: a machine draft must never be shown as final.
- **Legal and consent wording** (the privacy policy, terms and the consent notes under forms). It stays in English until a lawyer or a professional translator provides reviewed text.
- **The Guide's suggested-day reasons and the AI's answers.** (The AI replies in the language the visitor writes in.)
- **Page titles and descriptions** for search results (only the homepage's language links are set).

## Translation quality: please read before launch
The Kiswahili, French and German texts were **drafted for this project and have not been reviewed by native speakers.** Have a native Kenyan Swahili speaker read every Kiswahili text (tourism words differ between Kenya and Tanzania), and have French and German readers check theirs. The dictionary files say so at the top. Ask them to look especially at: the headings that break across two lines (they are translated as two lines that must read correctly one after the other), the Taita Guide's wording, and the passport and stamp terms.

## Search engines
Only pages that really exist in another language may say so. Today that is the homepage (language links in its `<head>` and four entries in the sitemap). A test fails if any other page declares translations. When you translate a page, add its language links and sitemap entries in the same change.

## A trade-off to know about
The page's language is read from the request, so pages are built when asked for rather than saved ahead of time. The homepage used to refresh itself every 60 seconds; it now builds per request. At today's size this is fine. The cleaner long-term design is a language folder in the page tree (`app/[locale]/…`), which keeps pages pre-built. It is a large change to every page, so it should be its own piece of work.

## Adding another language
Add it to `LOCALES` and `LOCALE_INFO` in `lib/i18n/config.ts`, add its dictionary file and register it in `lib/i18n/translate.ts`, then run the tests: they tell you every text it still needs.
